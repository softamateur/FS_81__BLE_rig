# Project: st_wiki_ble_cus_svc_freertos

"ST Wiki BLE custom service FreeRTOS"

* Modifed version of "st_wiki_ble_cus_svc_seq" that supports FreeRTOS
* Does not uses ST sequencer UTIL_SEQ
* Built from scratch using CUBE MX to implement STM32_WPAN BLE and FreeRTOS
* Demonstrates how to build a FreeRTOS BLE project from scratch using CUBE MX, or how to modify an exisiting CUBE MX project without losing the use of CUBE MX
* Can be tested using "ST BLE Toolbox" mobile app P2P service.
* Runs on the NUCLEO-WB55RG board.

## Description
This project is a evolution of the bare metal program: https://bitbucket.org/lundinova/st_wiki_ble_cus_svc_seq which is based on the ST Wiki example at:  

https://wiki.st.com/stm32mcu/wiki/Connectivity:STM32WB_BLE_STM32CubeMX

It is meant to be as identical as practical to the "st_wiki_ble_cus_svc_seq" project, only substituting FreeRTOS for the ST UTIL_SEQ sequencer.

## Caveats
The goal is to have a project that supports BLE via STM32_WPAN but also is compatible with FreeRTOS, and continues to be compatible with CUBE MX.
As examplied below, this is not provided by ST.

Note that the example provided by ST for a FreeRTOS project is:
\STM32Cube\Repository\STM32Cube_FW_WB_V1.24.0\Projects\P-NUCLEO-WB55.Nucleo\Applications\BLE\BLE_HeartRateFreeRTOS. However, the issues are:

1) This example uses a complicated folder structure and is incompatible with CUBE MX (ST's ECO own system!).

2) Creating an example from CUBE MX based on the "BLE_HeartRateFreeRTOS" will provide a "self contained" folder structure - but is still incompatible with 
CUBE MX as it is copied from the example. 

3) Finally, (as a 3rd option) creating a similar CUBE MX project from scratch (with BLE and FreeRTOS), the only options are to support the Heartrate service
or none at all (Heartrate disabled). No STM32_WPAN Custom service option is provided when FreeRTOS is used in CUBE MX. If Heartrate is disabled,
all of the critcal SCHI, HCI, debug trace and other code is removed by CUBE MX. If you leave Heartrate enabled in order to obtain this code from CUBE MX 
and the STM32_WPAN FW package, CUBE MX will likely clobber your code on the next code generation and will definately restore the Heartrate code(!).

In other words, no practical option is provided by ST to support a Custom service, the SCHI / HCI layer and FreeRTOS.

The meaning of this program ("st_wiki_ble_cus_svc_freertos") is to provide a program that supports STM32_WAPN BLE, FreeRTOS and CUBE MX, which can be used
as an example to build on or a guide to create a new program from scratch, or add BLE support to an existing CUBE MX FreeRTOS based program.

## Solution
* Prior to adding STM32_WPAN BLE to the project, FreeRTOS must be enabled in CUBE MX (at least the default task). This is CRITICAL so that CUBE MX "senses" that FreeRTOS is being used and generates the necessary RTOS objects for BLE tasks and does not implement the STM32 UTIL_SEQ sequencer.

* The following files are modifed or created manually:

app_conf.h      // USER CODE areas modified  
app_entry.c     // "  
app_ble.h       // "  
ble_conf.h      // "  
ble_dbg_conf.h  // "  

app_ble_alt.c    // New file based on app_ble.c normally generated by CUBE MX (renamed to ensure it is not clobbered during code regeneration)  

custom_app.c    // New file manually added to build (as CUBE MX cannot generate this)  
custom_app.h    // "  
custom_stm.c    // "  
custom_stm.h    // "  

* As STM32_WPAN uses printf() in newlib for debug tracing, threadsafe locks need to be implemented (and are in this example project). Refer to the following (Word document) for more information on threadsafe operation of newlib:

https://bitbucket.org/lundinova/threadsafe/src/master/

* CUBE MX generates a default FreeRTOS task "StartDefaultTask()" with a tight while() loop and osDelay(1). This can starve
the BLE threads so this should yield with something like osDelay(1000) instead. The exact task priorities can be returned to
later as this depends on the context of each project. 

## Development process
In following the guideline, first the CUBE MX project was generated from scratch with (first) FreeRTOS enabled and subsequently the STM32_WPAN middleware implemented to form the base project with only CUBE MX generated code.

To replicate this: 
* Start with CUBE MX (not CUBE IDE).
* Ensure that the STM32_WPAN FW has been installed (STM32WB). If not, go to Help->Manage embedded software packages in CUBE MX.
* Start a NUCELO-WB55RG board project in CUBE MX using the "board selector" option and choose NUCELO-WB55RG, Start Project.
* Deselect "Generate demonstration code".
* Deselect Virtual Com Port (you want to leave USART1 free for the BLE debug port UART). Note that you will configure USART1 later for the BLE program).
* Leave the buttons and LEDs selected.
* IMPORTANT: Enable FreeRTOS with at least one task (the default is fine)
* Follow the guide in the ST Wiki example (link above). HOWEVER, completely skip section: "5. BLE GAP/GATT Custom application configuration". This configures the Custom service which is not available in CUBE MX with FreeRTOS. Instead, go directly to section "6. Enable traces" to configure the BLE debug USART1. Skip section "7. P2P Server notifications and writes management". Instead, copy or modify the following files from this project:

app_conf.h      // modify USER CODE as needed  
app_entry.c     // "  
app_ble.h       // "  
ble_conf.h      // "  
ble_dbg_conf.h  // "  

app_ble_alt.c   // copy file
custom_app.c    // " 
custom_app.h    // "  
custom_stm.c    // "  
custom_stm.h    // "  

Direct file compare is suggested to do this.

* Implement the threadsafe solution mentioned above to avoid printf() newlib issues (make the entire newlib threadsafe).

## Summary
Although this requires a significant amount of implemention work, this repository supplies a working reference. It is suggested to build this project first and test on a NUCLEO-WB55RG board to have a working reference.

Note that since ST does not support Custom service with FreeRTOS, much of the code here can be cut and paste to change the services and characteristics manually as these are not generated by CUBE MX.
